# 정리하고 리셋 (wrap-up)

대화가 리셋(자동 요약·`/clear`)되면 진행 중이던 일·확인하기로 한 것·정한 사항이 흐려진다(11-24: 리셋 중 승인받은 푸시가 빠진 적 있음).
리셋 전에 이 순서로 정리한다. **자동 장치**: `scripts/session_snapshot.sh`가 자동 요약 직전(PreCompact 훅)에 기계적 상태를 저장하고,
리셋 직후(SessionStart 훅, compact·clear)에 이 노트 + 상태를 새 대화에 자동으로 넣는다(`.claude/settings.json`).

## 1. 상태 확인 (먼저)
```bash
bash scripts/session_snapshot.sh --inject
```
- **푸시 안 한 커밋**이 있으면: 사용자가 이 대화에서 이미 푸시를 승인했으면 지금 푸시·집 서버 반영(결정 006)까지 하고, 아니면 목록을 보여 주고 묻는다.
- **커밋 안 한 변경**이 있으면: 작업 중이던 것이면 work-report 절차로 마무리할지, 그대로 노트에 남길지 묻는다. (`data/pe_eps_cache.json`·`AGENTS.md`·`.agents/`는 원래 따로 관리 — 무시)
- **집 서버 코드가 main과 다르면**: 반영 승인을 받았는지 확인 후 반영하거나 노트에 남긴다.

## 2. 기록 확인
- 끝난 작업이 `docs/CHANGELOG.md`에 있는지, `docs/ROADMAP.md`의 끝난 항목이 지워졌는지.
- **아직 진행 중인 작업**은 ROADMAP "🔨 진행 중" 표에 한 줄(시작일·어디까지 했는지) 올린다.

## 3. 인수인계 노트 쓰기 — `logs/session-handoff.md` (덮어쓰기, git 제외 폴더)
아래 양식, 짧게(60줄 이내). 사실만 — 확인 안 한 것은 "미확인"으로.

```markdown
# 인수인계 노트 — YYYY-MM-DD HH:MM KST

## 이어서 할 일 (우선순위 순)
1. … (어디까지 했는지·다음 한 걸음)

## 확인 대기 (시각이 정해진 것)
- MM-DD HH:MM — 무엇을 확인 (예: 미국 첫 16:01 기록, 자동 점검 결과)

## 이번에 정한 것 (사용자 결정)
- … (예: 미국 거래대금 추정치는 쓰지 않음, 유료 데이터 보류)

## 서버 상태
- 작업 PC 5001 / 집 서버 반영 버전 / 감시 CT

## 사용자에게 받은 것·남은 질문
- …
```

## 4. 안내
"정리 끝났어요. 이제 `/clear` 하셔도 됩니다 — 리셋 직후 이 노트와 상태가 자동으로 다시 들어옵니다." 와 함께 노트 요약 3~5줄.

## 규칙
- 노트에 키·비밀번호를 쓰지 않는다. 서버 주소는 써도 되지만 노트는 `logs/`(git 제외)에만.
- 푸시는 여기서도 **승인받은 경우에만** (CLAUDE.md 필수 규칙 4).
- 리셋 직후 자동으로 들어온 상태에 "⚠️ 푸시 안 한 커밋"·"집 서버 ≠ main"이 있으면, 다른 일보다 먼저 사용자에게 알린다.
